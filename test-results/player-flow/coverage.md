# ชุดทดสอบ GUT 68 กรณี

ชุดนี้ใช้ GUT 9.7.1 / Godot 4.7 กรณีเดียวอาจมีหลายชุดข้อมูลหรือหลายกิจกรรม จำนวน 68 จึงเป็นจำนวนสถานการณ์ระดับรายงาน ไม่ใช่จำนวน assertion และไม่ใช่ทุกเส้นทางที่เป็นไปได้ของเกม

## รันเอง

ดับเบิลคลิก **`run-tests.cmd`** ที่โฟลเดอร์หลัก รายงานเปิดเมื่อรันจบ ใช้เวลาประมาณ 2–3 นาที ขึ้นกับเครื่อง

- ผลล่าสุด: `test-results/player-flow/latest.html`
- ผลย้อนหลังและข้อมูลทดสอบ: `test-results/player-flow/<วันเวลา>/`
- เก็บ HTML, JSON, JUnit XML และ console.log ไว้เป็นหลักฐาน
- เซฟ เสียง และอันดับทดสอบอยู่ใน sandbox ของแต่ละรอบ ไม่เขียนทับข้อมูลเล่นปกติ

```powershell
# ทดสอบเฉพาะเหตุการณ์และภารกิจ
.\run-tests.cmd -Suite test_play_events

# รันซ้ำกรณีเริ่มใหม่หลังจบเกม
.\run-tests.cmd -Test PLAY_END_05

# เปิดหน้าต่าง GUT; process ที่ทดสอบเปลี่ยนฉากยังคงเป็น headless
.\run-tests.cmd -ShowWindow

# ใช้ Godot ของเครื่องอื่น
.\run-tests.cmd -GodotPath "C:\Godot\Godot_v4.7-stable_win64_console.exe"

# ใช้กับ CI โดยไม่เปิดเบราว์เซอร์/ไม่หยุดรอปุ่ม
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\run-tests.ps1
```

Exit 0 = ผ่านหมดและไม่พบข้อผิดพลาดเครื่องยนต์, 1 = มี fail/pending/risky, 2 = รันไม่ครบหรือเกิดข้อผิดพลาดระหว่างรัน ชุดปัจจุบันไม่มีกรณี pending ที่กำหนดไว้ล่วงหน้า

## วิธีจำลองและขอบเขตหลักฐาน

- เรียกสัญญาณของปุ่มจริงโดยตรวจ visible/disabled และเรียกตัวจัดการ input จริงของฉาก ไม่ใช่การคลิกตำแหน่งเมาส์ผ่านระบบปฏิบัติการ
- กำหนดระยะใกล้อาคารเพื่อทดสอบ E โดยไม่ต้องเดินข้ามแผนที่ทุกกรณี การตรวจทางเดินและสิ่งกีดขวางอยู่นอกขอบเขตนี้
- เดินเวลาผ่าน `_process(delta)` และเร่งภาพเคลื่อนไหว ควบคุม seed เพื่อให้เหตุการณ์เกิดซ้ำ ใช้ฐานเหตุการณ์จริง ไม่เขียนทับฐานข้อมูล
- กรณีทั่วไปควบคุมสาขาที่ไม่มีสถานการณ์แทรก ส่วน PLAY-EVENT ตรวจสาขาสุ่มแยกต่างหาก สถานการณ์ทุก 43 ทางเลือกเริ่มจาก RNG seed ที่เลือกสถานการณ์นั้นได้จริง
- ไม่มีการตั้งเงิน/ค่าสถานะ/วันให้เป็นเงื่อนไขปลายทางโดยตรง: เงินเหลือ 20 เกิดจากยืมหนังสือจริง 49 ครั้ง; สลบจากวิ่ง; สัปดาห์สอง/สอบจากจบเทิร์น; level 6 จากเรียนตามตาราง
- ตัวช่วยสร้างรูปลักษณ์เริ่มต้นด้วยตัวจัดการบันทึกของ AvatarMenu; กรณีทดสอบคณะใช้ตัวเลือกคณะที่ถูกต้อง
- เส้นทางเปลี่ยนฉากและโหลดเปิด Godot อีก process ผ่านเมนูจริง มีเวลาสูงสุดป้องกันค้าง และใช้ข้อมูลทดสอบที่แยกไว้
- ผล pass หมายถึง **ส่วนอัตโนมัติที่ระบุในสคริปต์ผ่าน** ไม่ยืนยันผลภาพ/เสียง/กล้องหรือทุกขั้นตอนทางกายภาพในแผนจากการเล่นด้วยคน

## ขอบเขตที่ไม่นับในชุดนี้

ภาพ เสียงที่ได้ยินจากลำโพง กล้อง การเดินชนสิ่งกีดขวาง และผลโหมดจอจริงอยู่นอกขอบเขตชุด GUT นี้ ไม่ตั้งเป็น pending และไม่รวมในจำนวน 68 กรณี

## บั๊กเริ่มใหม่หลังจบเกมที่แก้แล้ว

**PLAY-END-05 — เริ่มใหม่หลังจบเกมยังเก็บความคืบหน้าเก่า**

ก่อนแก้ ทำซ้ำได้ด้วยการเริ่มเกม 1 คน อ่านหนังสือที่หอ 1 ครั้ง จบเทิร์นจนครบ 10 วัน ทำข้อสอบจนจบ แล้วกดเริ่มใหม่บนหน้าสรุป ความรู้ยังเป็น 5 ผลสอบ completed ยังอยู่ และคะแนนภารกิจเก่ายังอยู่ แม้วันกลับเป็น 1 และเวลาเป็น 06:00 โดยผลสอบเก่าคือถูก 20/20 ได้ 1,000 คะแนน และ mission_scores ยังมีคีย์วัน 1–10 อยู่ คาดหวังให้ความคืบหน้าเหล่านี้เริ่มใหม่

สาเหตุ: `_on_restart_pressed()` ใน `ui/endgame_ui.gd` รีเซ็ตค่ากลาง เช่น `Global.study_score` แต่ไม่รีเซ็ต `Global.player_data` ขณะที่ `_setup_mock_data()` ใน `locations/new_map.gd` สร้างค่าสถานะเฉพาะเมื่อยังไม่มีข้อมูล ดังนั้นข้อมูลรายผู้เล่นจากเกมเก่าจึงถูกใช้ต่อ

แก้ปุ่มเริ่มใหม่ให้เก็บเฉพาะจำนวนผู้เล่น คณะ และรูปลักษณ์ เรียก `SaveManager.start_new_game()` และ `Global.setup_players(count)` เพื่อสร้างข้อมูลเล่นใหม่ จากนั้นคืนตัวเลือกตัวละครและโหลดแผนที่ ปุ่มถูกปิดระหว่างเริ่มใหม่เพื่อกันกดซ้ำ

PLAY-END-05 ตรวจจากการเล่นจนจบจริงสำหรับผู้เล่น 1/2/3/4 คน ยืนยันวัน/เวลา เงินและสถานะเริ่มต้น ความรู้ ระดับวิชา ผลสอบ ภารกิจและประวัติเหตุการณ์ถูกล้าง คณะ/รูปลักษณ์และจำนวนผู้เล่นคงเดิม ตารางยังไม่เรียน ช่องเซฟไม่ผูกกับเกมเก่า และไฟล์เซฟ/อันดับเดิมไม่เปลี่ยน ดูผลล่าสุดในรายงาน
